# Planning documents

Live plans for changes to petpermit.co.uk. Each plan is reviewed by Swasti **before** any website
change it describes is made.

## How these work

1. A plan is written here first, one file per topic, named `YYYY-MM-DD-topic.md`.
2. Swasti reviews it and answers the **Decisions needed** at the bottom.
3. Work happens one item at a time. Each website change is its own commit, and the commit message
   names the plan item it fixes (for example `AI-SEO #1`).
4. The plan stays live: its status table is updated as items move from **Proposed** → **Approved**
   → **In progress** → **Done** (or **Dropped**), with the date and commit.
